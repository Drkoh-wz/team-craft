# 禁止「let me」句式中断

## 为什么存在

当前模型在与 DSH 交互时，反复以 `let me ...` 这类句式开头做「思考旁白」，然后**自行中断工具调用链**返回给用户，造成一轮轮无进展、令人沮丧的空转。该 skill 用于强制纠正这一行为。

## 触发

每当模型在工具调用序列中写出 `let me ...` / `let me check ...` / `let me read ...` / `let me verify ...` / `let me look ...` 等句式，或任何形式的「我先 …」自述旁白时，本 skill 即被触发。

## 规则（强约束）

1. **禁止在工具调用之间插入「let me」旁白**。工具调用应当连续、一次性在单个回合内按需发出，直到结果齐备或明确阻塞，再向用户汇报。
2. **「let me」句式的本质是把本该由工具完成的事口头化**。改为：直接用工具。要检查 → 调用 `read`/`pwsh`/`cordis_inspect_*`；要确认 → 调用相应 inspect/query。不表述、直接做。
3. **不要自行中断**。若下一步依赖某结果，就连续发出依赖链上的工具调用（可并行就并行），并 `await`/收集结果；不要停在「我先确认一下」。仅在真正阻塞（需用户提供信息/权限、或无法从工具获得）时才返回。
4. **用陈述、不用旁白**。需要说话时用陈述句说明「正在…」「已获取 X」，而不是「让我看一下 X」。

## 每触发一次的副作用

每次模型写出 `let me` 句式（或等价自述旁白）：
- 向当前任务上下文**追加一个新任务项**：`继续推进当前目标：<复述被旁白打断了的目标/步骤>`，状态 pending。
- 后续回合优先处理该追加任务，禁止把它丢在一边又开新旁白。

## 自检

- 一个回合内是否同时出现了「let me …」和实际工具调用？若有，旁白违规，删掉旁白。
- 是否在一次可以连续完成的序列中间隔了「我先…」？若有，中断违规。
- 是否在结果已足够推进时仍返回给用户？若有，空转违规。

## 遵守

本 skill 是对模型行为的最强制约之一。违反即视为未正确执行当前任务。

## 结束会话前的完成检查（强约束）

在每次准备结束回合、向用户交回控制权之前，**必须先自检本回合的目标是否真正完成**，未完成则不得返回，必须继续：

1. **目标是否完成**：本回合用户的请求 / 当前任务项的完成标准是否已达成？若只做了一半（如创建了文件但没验证、调了工具但没取结果、说要创建任务但没调用工具），视为未完成，继续。
2. **是否兑现了承诺**：本回合中若说「我来创建 X」「我先调用 Y」「现在…」，检查这些动作是否真的执行了；没执行就继续执行，不空口返回。
3. **是否有未取回结果的工具**：本回合是否发起了工具调用但尚未读取其结果、或尚未根据结果推进下一步？若有，继续取结果 / 推进，不返回。
4. **是否因「旁白」而不是「阻塞」停下**：停下返回的唯一正当理由是真正阻塞（需要用户提供信息/权限/决策、或能力上限），不是因为想「先歇一下」或「先看看」。非阻塞时一律继续，直到达成完成标准或明确卡在需要用户处。
5. **未完成时如何继续**：直接调用下一步工具（可能并发发出），不许加旁白、不许先解释为什么继续、不许先问「要我继续吗」。继续本身默认被授权。

通过自检确认目标真正完成后，才允许返回给用户，并在返回里陈述「已完成/已验证」的事实。
